DaT Parkinson's Challenge

Classifying a dopamine-transporter (DaT) SPECT brain scan as normal or abnormal, from the scan alone.

Built for DrivenData's DaT Parkinson's Challenge (French Society of Nuclear Medicine, 2026), closed 2026-09-16. Source: github.com/Alherma7/DaT_Parkinson.

The problem

A DaT scan images dopamine transporter density in the striatum. The data: 1,362 training scans from ten French hospital centers, 3D NIfTI volumes with variable dimensions and voxel spacing, no site/scanner label provided. Two facts shaped every design decision:

  • 40% of volumes have oblique affines (up to 40.3° tilt) despite all reporting RAS axis codes — resampling has to go through the affine, not just permute axes.
  • The metric is log loss, a proper scoring rule — calibration matters as much as discrimination (AUROC is shown only for reference).

The final pipeline

1. Resample each NIfTI to physical spacing (not a fixed voxel shape), affine-aware — oblique volumes need a real affine resample, not just axis permutation.
↓
2. Locate the striatum per subject and crop around each subject's own measured centroid, replacing an earlier fixed population-median crop center.
↓
3a. Classical baseline — handcrafted asymmetry/ratio features, ComBat-harmonized (Fortin et al. 2018) logistic regression correcting for the scanner-family confound.
3b. 3D CNN trained on the per-subject-centered crops.
↓
4. Blend — CNN + classical baseline, logit-space temperature-calibrated weighted average; weights and temperatures selected via leave-one-fold-out validation, never on the data used to score the final recipe.

The key finding: a coverage bug, not a modeling problem

The production crop was centered on a single, fixed point: the population median offset of the striatum, measured on a small stratified sample. That point missed the actual striatum for roughly 30% of subjects. The clearest evidence came from decomposing AUROC by whether each subject's striatum centroid fell inside the fixed crop:

The CNN's discrimination collapses specifically on the subjects the crop missed (AUROC 0.9293 → 0.7088), while the crop-immune classical baseline barely moves (0.8112 → 0.7666). That isolates the fixed crop itself — not general subject difficulty — as the cause, and rules out recalibration as a fix: this is a discrimination failure, not a confidence problem. Retraining with each subject cropped around their own measured centroid (100% coverage by construction) produced the largest single result of the project: −0.1025 log loss, 95% CI [−0.1449, −0.0601].

Lessons

Measure honestly before you improve

The single biggest "free" win in this project (−0.0393 log loss) was not a new technique — it was discovering that the production model (a 25-checkpoint average) had never actually been scored as itself. The registered gate had been scoring a different, smaller quantity. Fixing the measurement came before any of the real modeling gains.

A statistics bug can hide (or fake) a real result

An early gate compared a 5-repeat mean against twice a single repeat's standard deviation instead of the mean's standard error — a 4.5–7.7σ bar in practice. Two experiments (cosine LR schedule, augmentation) were directionally positive the whole time; the bug never hid a result that should have passed, but a less conservative bug easily could have.

The biggest lever came from questioning a basic assumption, not a fancier model

Ten times larger than any other single change, the crop-coverage fix came from re-examining a geometric assumption (a fixed crop center) that had never been directly measured against the data — not from a new architecture, more data, or more compute. It was found indirectly, while investigating why an unrelated 2D architecture experiment failed.

Submission-time score and final leaderboard score can diverge

The best score this project ever produced (0.2975 log loss) was observed at submission time, on the last submission. The confirmed final result is 0.3436 — a real gap, not a reporting error, and consistent with the wider divergence between public and private standings reported across this competition's field.

Reproduce

This repository contains no scan data, per-patient labels, per-patient predictions, or trained weights — only code, configuration, and aggregate metrics, per the competition rules.

conda env create -f environment.yml
conda activate dat-parkinson

# all pipeline code is under test with synthetic data
pytest

# notebooks/01 .. 27 reproduce the full experimental record in order,
# from EDA through the final coverage-fix retrain

# package a submission from submission_src/
python scripts/build_submission_assets.py
